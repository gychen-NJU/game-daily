# 坐标模型与首次校准

## 1. 原则

**坐标永远只是参考值，第一次使用必须按当前机器实际情况校准。**

理由：模块里内置的坐标来自一台特定电脑（Windows 11 / 2560×1600 / 100% 缩放 / 游戏全屏）。换分辨率、缩放比、窗口模式、甚至游戏版本改版，坐标都会偏。所以：

- 文件里存的坐标是**相对坐标**（`rx = x/宽`，`ry = y/高`），换分辨率时按比例换算不会整体跑偏；
- 每台机器校准后的**绝对坐标**写进本机私有文件 `state/coords.local.json`，解析时**优先用它**；
- 没校准且相对坐标换算后仍然点不中 → **停手问用户**，不要连续盲点。

## 2. 文件

| 文件 | 归属 | 内容 |
|---|---|---|
| `references/<game>-coords.json` | 模块（随技能分发） | 默认相对坐标 + 说明 + 易错点 |
| `state/coords.local.json` | **本机私有**（不复制、不分发） | 校准后的绝对坐标；可含本机屏幕尺寸 |
| `state/shots/` | 本机私有 | 校准与运行时的截图 |

`state/coords.local.json` 结构：

```json
{
  "base": { "w": 2560, "h": 1600 },
  "calibratedAt": "2026-10-23T05:30:00+08:00",
  "items": {
    "guide.task_claim": { "x": 540, "y": 1182, "note": "本机：卡片第二张时按钮在 540" }
  }
}
```

## 3. 什么时候校准

满足任一条件即进入校准模式：

1. 第一次在这台机器上跑（`state/coords.local.json` 不存在）；
2. `probe.mjs` 报的屏幕尺寸与模块 `base` 不一致；
3. 连续两个目标点"点了没反应"（先复核坐标，而不是继续点）；
4. 游戏大版本更新后第一次运行。

只校准**用到的**点即可（不必 19 个全做）。`coords.mjs calibrate` 会列出还没校准的 id。

## 4. 校准流程（单点）

1. 用适配器把界面切到目标步骤（例如先 F4 打开指南）。
2. `shot` 截图，**自己看图**找到目标控件（按钮/图标），读出它在**截图文件**里的像素位置 `(px, py)`。
3. 换算成屏幕物理像素：`x = origin.x + px / imageScale`，`y = origin.y + py / imageScale`（没有缩放时 `imageScale = 1`、`origin = 0`）。
4. 写到本机：
   ```powershell
   node ..\game-daily\scripts\coords.mjs set guide.task_claim 540 1182 --game sr --note "卡片第1张时的领取"
   ```
5. **复检**：立刻用这个坐标点一次，截图确认目标状态真的变了（按钮变灰 / 弹结算 / 数值增加）。没有变化就重来。
6. `node ..\game-daily\scripts\coords.mjs resolve guide.task_claim --game sr` 应显示 `source: local`。

## 5. 校准记录要求

- 每个点至少一句 `note`：**什么界面状态下**测的（例如"列车补给弹窗已关"/"卡片滚动到第一张"）。
- 校准完成后在 `state/calibration.log.md` 追加一段：日期、屏幕尺寸、缩放、游戏版本、已校准 id 列表。
- 不许把校准值回写到模块的 `references/*-coords.json`（那是出厂参考值，跨机器复用会被污染）。

## 6. 易错点（来自实跑）

| 点 | 坑 |
|---|---|
| `guide.task_claim` | 指南任务卡是**横向滚动**的，按钮 x 随卡片位置变化；同一 id 在不同轮次可能是不同卡片 → 文档里同时给了"以当前截图为准"的判定 |
| `honor.onekey_mission` | 「一键领取」实际在 y≈1300（相对 0.8125），**不是**视觉上更低的 0.8625；差 80px 就点空 |
| `calyx.plus` | 「+」在挑战次数滑条右端，y≈1266；点低了会落到资源条上（无害但没效果） |
| `dispatch.claim_reward` | 领取后按钮会变成"委托派遣中"占位，再点同一位置没反应是正常的 |
| 所有点 | 弹窗（"获得物品"）出现时先点空白关闭（`popup.close_blank`），否则后续点击会被遮罩吞掉 |
